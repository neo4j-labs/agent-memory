== General questions

[[what-is-neo4j-agent-memory]]
=== What is neo4j-agent-memory?

Neo4j Agent Memory provides Python and TypeScript SDKs for persisted conversations, reusable knowledge, and recorded task execution. It is an experimental, community-supported Neo4j Labs project. See xref:index.adoc[the overview] and xref:explanation/memory-types.adoc[the three memory types].

[[what-is-poleo]]
=== What is the POLE+O data model?

POLE+O means Person, Object, Location, Event, and Organization. These broad entity categories can be refined with subtypes or domain schemas. See xref:explanation/poleo-model.adoc[the POLE+O model].

[[need-neo4j]]
=== Do I need my own Neo4j to use this package?

You can use hosted NAMS with an authorized workspace and API key, or connect Python directly to a Neo4j database through Bolt. The backends share concepts but support different operations and return shapes. See xref:reference/backend-capabilities.adoc[Backend capabilities] and xref:getting-started.adoc[Getting started]. Python's local extraction components can also operate on text independently of storage.

[[whats-not-on-nams]]
=== What's not available on the NAMS backend?

NAMS manages extraction, embeddings, and resolution server-side. Python client-side settings do not configure those services, and several Bolt operations are unsupported on the hosted transport. See xref:reference/backend-capabilities.adoc[the per-operation capability table] rather than assuming that an accessor or similarly named method is supported on both backends.

[[which-sdk]]
=== Which SDK should I use — Python or TypeScript?

Choose by language and backend. Python supports Bolt and NAMS; TypeScript targets NAMS REST. Agents can share supported records in the same authorized workspace, but the APIs and capabilities are not identical. See xref:sdks/python.adoc[Python], xref:sdks/typescript.adoc[TypeScript], and xref:reference/backend-capabilities.adoc[Backend capabilities].

[[what-are-skills]]
=== What are NAMS Agent Skills? _(Preview)_

Agent Skills is a NAMS preview feature that derives a portable procedure package from scoped memory. Provenance links support review of the generated procedure; they do not establish that every source claim is correct. See xref:explanation/skills.adoc[Agent Skills] and xref:reference/skills-api.adoc[the REST and MCP interface].

[[run-a-skill]]
=== Can I run a distilled skill? _(Preview)_

Downloading a published skill and loading it into an agent is separate from server-side distillation. The documented execution feature is gated dry-run planning, not automatic tool execution. See xref:reference/skills-api.adoc[Skills API] for its limits and xref:tutorials/skills-quickstart.adoc[the skill walkthrough] for the demonstrated outcome.

[[neo4j-versions]]
=== Which Neo4j versions are supported?

For Bolt, use the database prerequisites in xref:getting-started.adoc[Getting started] and the vector-index requirements in xref:reference/configuration.adoc[Configuration]. The Python Neo4j driver version is not the database server version. NAMS users do not manage the service's Neo4j version.

[[aws-support]]
=== Does neo4j-agent-memory work with AWS?

Python provides a Bedrock embedding adapter, a Strands integration, and AgentCore memory components. Each has its own dependencies and supported behavior; this is not a claim of universal AWS feature support. See xref:how-to/integrations/aws-bedrock-embeddings.adoc[Bedrock embeddings], xref:how-to/integrations/aws-strands.adoc[Strands], and xref:how-to/integrations/aws-hybrid-memory.adoc[Hybrid memory].

[[bedrock-credentials]]
=== How do I configure AWS credentials for Bedrock embeddings?

The Bedrock adapter uses the AWS SDK credential chain. The identity needs permission for the selected model and region. Follow xref:how-to/integrations/aws-bedrock-embeddings.adoc[Configure Bedrock embeddings] for the supported settings and credential setup.

[[strands-vs-direct]]
=== Should I use Strands tools or the MemoryClient directly?

Use Strands tools when an agent should choose a memory operation through its tool interface. Use `MemoryClient` when application code should control the operation directly. A tool is only called when the agent or application invokes it. See xref:how-to/integrations/aws-strands.adoc[the Strands integration].

== Entity extraction pipeline

[[how-pipeline-works]]
=== How does the extraction pipeline work?

Python's Bolt pipeline runs configured extraction stages and combines their candidates. Stages differ in vocabulary, resource requirements, and failure modes. See xref:explanation/extraction-pipeline.adoc[How extraction works] for the design and xref:how-to/entity-extraction.adoc[Configure extraction] for the procedure.

[[single-extractor]]
=== Can I use just one extractor instead of the full pipeline?

Yes. An extractor can be used independently of a multi-stage pipeline. Choose a component with the entity and relation capabilities your task needs. See xref:reference/extractors.adoc[Extractor classes] and xref:how-to/entity-extraction.adoc[Configure extraction].

[[merge-strategies]]
=== What are merge strategies?

Pipeline merge strategies combine candidates from extraction stages. The implemented names are `union`, `intersection`, `confidence`, `cascade`, and `first_success`; this differs from deduplicating entities already stored in the graph. See xref:explanation/extraction-pipeline.adoc#_merge_strategies[How results combine] and xref:reference/extractors.adoc[the exact API].

[[which-extractor]]
=== Which extractor should I use?

Compare the required labels and relationships, local versus remote processing, resource limits, and quality on representative text. No extractor is universally fastest or most accurate. GLiREL and LLM extraction can both produce relationships. See xref:explanation/extraction-pipeline.adoc[Extraction tradeoffs].

== GLiNER and domain schemas

[[schemas-gliner-only]]
=== Are domain schemas only used with GLiNER?

Python's `DomainSchema` configures GLiNER labels and descriptions. Other schema concepts are separate: spaCy has model-defined labels, LLM extraction has a response schema, and NAMS ontologies define a hosted graph vocabulary. See xref:reference/schemas.adoc[Domain schemas] and xref:explanation/ontologies.adoc[Ontologies].

[[labels-vs-schemas]]
=== What's the difference between entity labels and domain schemas?

Labels name the desired entity categories; a domain schema also gives those labels descriptions and can describe relation types. Descriptions clarify the intended vocabulary, but their effect on quality depends on the model and text. See xref:how-to/entity-extraction-schemas.adoc[Use extraction schemas].

[[schemas-with-pipeline]]
=== Can I use domain schemas with the full pipeline?

Yes. A GLiNER schema can configure that stage inside a pipeline. It does not automatically change every other stage's vocabulary. See xref:how-to/entity-extraction.adoc[Configure the pipeline] and xref:reference/extractors.adoc[Extractor builder reference].

[[which-schema]]
=== Which schema should I use?

Choose a vocabulary matching what the application needs to retain, then inspect representative outputs. The xref:reference/schemas.adoc[domain schema catalog] lists available schemas; xref:how-to/entity-extraction-schemas.adoc[the schema guide] explains how to apply or customize them.

[[custom-schemas]]
=== Can I create custom schemas?

Yes. Define the entity labels and descriptions for the GLiNER task, using the actual `DomainSchema` fields. See xref:how-to/entity-extraction-schemas.adoc[Use custom extraction schemas]. For hosted graph validation, use xref:how-to/use-ontologies.adoc[NAMS ontologies] instead.

[[poleo-mapping]]
=== Do schema entity types map to POLE+O types?

Extractor label mappings translate selected labels into POLE+O types and subtypes. A mapping does not prove that the model identified the entity correctly. See xref:reference/schemas.adoc[Schema mappings] and xref:explanation/poleo-model.adoc[POLE+O].

== spaCy extraction

[[spacy-entity-types]]
=== What entity types does spaCy recognize?

The available labels depend on the installed spaCy language model. Common English-model labels include `PERSON`, `ORG`, `GPE`, and `LOC`; the library maps recognized output into its entity vocabulary. See xref:reference/extractors.adoc[the spaCy extractor] for the integration contract.

[[spacy-custom-types]]
=== Can I use custom entity types with spaCy?

Changing a GLiNER schema does not change spaCy's trained NER labels. A custom spaCy model or additional application extraction logic is a separate approach. See xref:explanation/extraction-pipeline.adoc[the extractor tradeoffs] before selecting that path.

[[spacy-model-choice]]
=== Which spaCy model should I use?

Use a model for the document language and label requirements, and compare it on representative text. Download size, runtime memory, speed, and quality vary by model release and workload. Follow xref:how-to/entity-extraction.adoc[the extraction guide] for the configured model and installation steps.

== LLM extraction

[[when-use-llm]]
=== When should I use the LLM extractor?

An LLM can help when extraction depends on broader context or a response schema. It adds provider calls and potential failures; it is not guaranteed to outperform local extraction. Relationship extraction is also available with GLiREL. See xref:explanation/extraction-pipeline.adoc[Extraction approaches].

[[llm-models]]
=== What LLM models are supported?

`LLMEntityExtractor` can use the library's provider protocols and adapters, including supported native and LiteLLM paths. Model availability and structured-output support depend on the selected provider. See xref:reference/api/adapters.adoc[Adapters] and xref:how-to/configure-llm-provider.adoc[Configure an LLM provider].

[[local-llms]]
=== Can I use local LLMs?

Yes, through a supported provider adapter or a custom provider implementation. A local model must satisfy the interface and extraction requirements of that path; changing an OpenAI environment variable alone is not a universal configuration method. See xref:how-to/bring-your-own-model.adoc[Bring your own model].

[[llm-slow]]
=== Why is LLM extraction slow?

Generation time, network latency, input size, retries, and provider limits contribute to extraction latency. Compare the required quality against that cost, and use bounded concurrency. See xref:explanation/structured-extraction.adoc[Structured extraction] and xref:how-to/entity-extraction-batch.adoc[Batch extraction].

== Batch and streaming extraction

[[batch-extraction]]
=== How do I process multiple documents at once?

Use the batch API for the selected extraction or message-storage operation. Its result shape, concurrency controls, and failure behavior depend on that operation. Follow xref:how-to/entity-extraction-batch.adoc[Batch extraction] or xref:how-to/batch-processing.adoc[Batch message processing].

[[streaming-extraction]]
=== How do I handle very long documents?

Chunk documents when their length or structure exceeds the selected extractor's useful input window. There is no universal 100K-token cutoff. `StreamingExtractor` uses character-based `chunk_size` and `overlap` by default; `chunk_by_tokens=True` selects token-based chunking. See xref:how-to/entity-extraction-batch.adoc[Streaming extraction] for the supported calls.

[[relation-extraction-llm-free]]
=== Can I extract relationships without LLM calls?

Yes. GLiREL can predict relationships alongside local entity extraction. It requires its own model and compute resources, even when it avoids remote LLM API calls. See xref:reference/extractors.adoc[GLiREL reference] and xref:how-to/running-without-an-llm.adoc[Run without an LLM].

== Entity resolution and deduplication

[[what-is-resolution]]
=== What is entity resolution?

Resolution decides whether different mentions refer to the same entity. Similarity is evidence to investigate, not proof of identity. See xref:explanation/resolution-deduplication.adoc[Resolution and deduplication].

[[resolution-strategies]]
=== What resolution strategies are available?

Python's Bolt resolution components use exact, fuzzy, semantic, or composite matching. Ingestion deduplication has separate configuration, and NAMS owns its server-side behavior. See xref:reference/configuration.adoc[Resolution settings] and xref:reference/backend-capabilities.adoc[Backend capabilities].

[[resolution-type-aware]]
=== Is resolution type-aware?

Type constraints can prevent some false matches, but the behavior depends on the resolver and its configuration. Even same-type entities can be different people or product variants. See xref:explanation/resolution-deduplication.adoc[Identity evidence] and xref:how-to/deduplication.adoc[Configure deduplication].

[[deduplication-on-ingest]]
=== How does entity deduplication on ingest work?

Bolt's `DeduplicationConfig` uses separate automatic-merge and review thresholds. Its defaults are `0.95` and `0.85` respectively; these are similarity cutoffs, not calibrated correctness probabilities. See xref:reference/api/long-term.adoc[the long-term API] and xref:how-to/deduplication.adoc[the review workflow]. NAMS uses its service-side contract.

[[same-as-relationships]]
=== What are SAME_AS relationships?

A `:SAME_AS` edge can record a candidate duplicate for review while preserving both records. Its presence is not a completed merge or a guarantee of identity. See xref:explanation/resolution-deduplication.adoc[the review pattern] and xref:how-to/deduplication.adoc[Review duplicates].

== Neo4j and storage

[[indexes]]
=== What indexes does the package create?

Bolt manages constraints and indexes needed by its configured schema and search features. Index names, dimensions, and requirements belong in xref:reference/schema-objects.adoc[Schema objects] and xref:reference/configuration.adoc[Configuration]. NAMS manages its own storage indexes.

[[entity-labels]]
=== How are entities labeled in Neo4j?

On Bolt, managed entities carry `:Entity`, a type property, and supported type/subtype labels such as `:Person` or `:Vehicle`. See xref:explanation/poleo-model.adoc[POLE+O] and xref:reference/schema-objects.adoc[Schema objects] for the distinction between stored labels and conceptual categories.

[[query-by-type]]
=== Can I query entities by type directly?

Supported type filters and, on permitted Cypher surfaces, node labels can select entity categories. The query must match the actual backend schema and scope. See xref:how-to/entities.adoc[Work with entities] and xref:reference/backend-capabilities.adoc[Backend capabilities].

== CLI tool

[[cli-installation]]
=== How do I install the CLI?

Install the package with the CLI extra and any extraction/provider extras needed by the chosen command. Follow xref:reference/cli.adoc[CLI installation and commands] for the exact package and invocation syntax.

[[cli-usage]]
=== How do I use the CLI?

The CLI supports extraction and related utilities through its implemented commands. Use xref:reference/cli.adoc[the CLI reference] for arguments, flags, input modes, and output formats; command names from older examples may not exist.

[[cli-configuration]]
=== How do I configure the CLI?

The current CLI constructs `MemorySettings`, which supports the documented environment variables and `.env` loading. It does not automatically load a `.neo4j-memory.yaml` configuration file. See xref:reference/cli.adoc[CLI configuration] and xref:reference/environment-variables.adoc[Environment variables].

== Geocoding and geospatial queries

[[geocoding-enable]]
=== How do I enable geocoding for LOCATION entities?

Geocoding is a configurable Bolt capability. Use xref:reference/configuration.adoc[Geocoding configuration] and xref:reference/api/long-term.adoc[the location API] for the actual settings and supported operations. Client-side geocoding settings do not configure NAMS.

[[geocoding-providers]]
=== What geocoding providers are supported?

The Bolt configuration exposes Nominatim and Google geocoding providers. Their credentials, service policies, quotas, and availability must be checked for the selected deployment; neither provider is universally more accurate. See xref:reference/configuration.adoc[Geocoding settings].

[[geocoding-batch]]
=== How do I geocode existing locations?

The Bolt long-term API includes an operation for geocoding stored locations. Its parameters and returned statistics are documented in xref:reference/api/long-term.adoc[Long-term memory]. Check those fields rather than assuming it shares the batch-extraction signature.

[[geospatial-queries]]
=== What geospatial queries are supported?

The Bolt long-term API supports location searches such as proximity and bounds, subject to stored coordinates and the method's scope. See xref:reference/api/long-term.adoc[Location operations] and xref:reference/backend-capabilities.adoc[Backend support].

[[geocoding-skip]]
=== Can I disable geocoding for specific entities?

Use the supported per-entity geocoding controls when adding an entity on Bolt. Explicit coordinates and automatic geocoding are separate inputs; use the exact types in xref:reference/api/long-term.adoc[the entity API].

== Observability and tracing

[[observability-setup]]
=== How do I enable tracing?

The observability module provides tracer objects and span/decorator helpers. Obtaining a tracer does not automatically instrument every memory or model operation. Instrument the application's selected operations; distinguish these spans from xref:how-to/reasoning-traces.adoc[stored reasoning traces] and xref:how-to/audit-reasoning.adoc[audit records].

[[what-is-traced]]
=== What operations are traced?

Only operations connected to the selected instrumentation are traced. Available attributes depend on what the application or adapter records; token counts and cost data are not implied for every operation. See xref:how-to/reasoning-traces.adoc[Reasoning traces] for the separate persisted task record.

[[opik-vs-otel]]
=== Should I use OpenTelemetry or Opik?

Choose an observability integration that matches the application's monitoring system and required data. OpenTelemetry provides general tracing interfaces; Opik's integration targets LLM application observability. The selected instrumentation still determines which spans and attributes exist.

== Performance and optimization

[[speed-up-extraction]]
=== How can I speed up extraction?

Measure which stage dominates the actual workload, then evaluate changes to enabled stages, model choice, batching, and concurrency. Track quality as well as runtime. See xref:explanation/extraction-pipeline.adoc[Extraction tradeoffs] and xref:how-to/entity-extraction-batch.adoc[Batch and streaming extraction].

[[memory-footprint]]
=== What's the memory footprint?

Runtime memory depends on the installed model, precision, device, input sizes, and concurrency. Model download size is not the same as peak process memory. Measure the configured environment; the docs do not provide a portable RAM estimate for every extractor.

[[caching]]
=== Can I cache extraction results?

Application-level caching can reuse completed extraction results when the text, model, schema, and configuration are unchanged. Cache the completed value, not an asynchronous coroutine object: `functools.lru_cache` applied directly to an `async def` does not provide a safe reusable result cache. Define invalidation and size limits for the application's workload.

== Troubleshooting

[[gliner-download-fails]]
=== GLiNER model download fails

Check the selected model identifier, access permissions, network access, and any configured offline mode. If using a local model path, confirm the required files are present. See xref:how-to/entity-extraction.adoc[the model setup procedure].

[[spacy-model-not-found]]
=== spaCy model not found

Installing the spaCy package does not necessarily install the configured language model. Install the exact model named by the extraction configuration, then rerun the extraction guide's verification. See xref:how-to/entity-extraction.adoc[Configure extraction].

[[low-accuracy]]
=== Low extraction accuracy

Compare labeled expected entities and relations with actual output. Inspect domain vocabulary, ambiguous names, filtering, and chunk boundaries before changing thresholds. Lower thresholds may improve recall while adding false positives. See xref:explanation/extraction-pipeline.adoc[Extraction tradeoffs].

[[filtered-incorrectly]]
=== Entities being filtered incorrectly

Check the extracted name against the implemented entity validation and stopword rules, then inspect the unfiltered result. See xref:reference/extractors.adoc[Extractor and validation reference] for supported helpers rather than relying on an example's assumed filtering API.

[[memory-errors]]
=== Memory errors with large texts

Reduce input chunk size or concurrency according to the extractor's limits, and inspect peak runtime memory. Preserve enough overlap to retain useful context at boundaries. See xref:how-to/entity-extraction-batch.adoc[Batch and streaming extraction].

[[extra-forbidden-from-env]]
=== Why does `MemorySettings(...)` raise `extra_forbidden` for `neo4j_uri` / `openai_api_key`?

Check for misspelled settings and the environment-loading behavior of the installed package. Current source filters unrelated `.env` keys while retaining strict validation of settings fields. Do not globally disable validation merely to hide an unknown key. See xref:reference/configuration.adoc[Settings] and xref:reference/environment-variables.adoc[Environment variables]; compare the installed release before assuming a source fix is available there.

[[gliner-not-installed]]
=== ImportError: GLiNER not installed

GLiNER is optional. Install the specific extraction extras declared by xref:how-to/entity-extraction.adoc[the guide] in the environment running the program. A broad extra does not necessarily include local models, and installing a Python package does not download every model.
