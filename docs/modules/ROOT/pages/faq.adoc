This document answers common questions about neo4j-agent-memory, with a focus on the entity extraction pipeline and domain schemas.

== General Questions

[[what-is-neo4j-agent-memory]]
=== What is neo4j-agent-memory?

neo4j-agent-memory is a Python package that provides a comprehensive memory system for AI agents using Neo4j as the backend. It implements three memory types:

* *Short-Term Memory* — Conversations and messages
* *Long-Term Memory* — Entities, preferences, and facts (using the POLE+O data model)
* *Reasoning Memory* — Reasoning traces and tool usage patterns

See xref:index.adoc[Overview] for more details.

[[what-is-poleo]]
=== What is the POLE+O data model?

POLE+O stands for **P**erson, **O**bject, **L**ocation, **E**vent, **O**rganization. It's a data model commonly used in law enforcement and intelligence analysis for organizing entities and their relationships.

The package extends this with optional subtypes (e.g., `OBJECT:VEHICLE`, `LOCATION:ADDRESS`).

See xref:explanation/poleo-model.adoc[POLE+O Data Model] for complete documentation.

[[need-neo4j]]
=== Do I need my own Neo4j to use this package?

No — you have two options. Use the hosted **NAMS** backend (sign up at link:https://memory.neo4jlabs.com[memory.neo4jlabs.com], set `MEMORY_API_KEY`, and there's nothing to run), or run your own Neo4j and use the **bolt** backend. The `MemoryClient` API is identical either way; see xref:explanation/backends.adoc[Bolt vs NAMS].

You can also use the **entity extraction features independently** without any backend — the bolt-side extraction pipeline works standalone and returns Python objects.

[[whats-not-on-nams]]
=== What's not available on the NAMS backend?

NAMS runs embedding, extraction, resolution, and enrichment server-side, so the client-side configs for those are ignored. A handful of bolt-only accessors raise `NotSupportedError` on NAMS: `client.users`, `client.buffered`, `client.consolidation`, `client.graph`, `schema.adopt_existing_graph()`, the geospatial methods, and the manual dedup-review methods. See the xref:explanation/backends.adoc#capability-matrix[capability matrix] for the full list and what NAMS does instead.

[[which-sdk]]
=== Which SDK should I use — Python or TypeScript?

Both share the same memory model and the same NAMS backend, so pick by stack. The **Python SDK** supports *both* backends (bolt and NAMS) and the full extraction/enrichment pipeline. The **TypeScript SDK** is **NAMS-only** (a `fetch`-based HTTP client) and ideal for Node, Bun, Deno, Cloudflare Workers, and Vercel Edge. Mixed Python + TypeScript agents can read and write the same memory on a shared workspace. See xref:sdks/python.adoc[Python SDK] and xref:sdks/typescript.adoc[TypeScript SDK].

[[what-are-skills]]
=== What are NAMS Agent Skills? _(Preview)_

Skills are a NAMS feature that *distils* a scoped slice of a workspace's accumulated memory — messages, entities, and reasoning traces — into a portable, provenance-grounded **Agent Skill** (an agentskills.io `SKILL.md` package) that another agent can load and reuse. Every claim and step is grounded in specific source nodes, so a skill is auditable rather than invented. Skills are exposed over REST and MCP only (there is no SDK method yet), and the feature is in **Preview**. See xref:explanation/skills.adoc[Agent Skills] and xref:reference/skills-api.adoc[Skills API].

[[run-a-skill]]
=== Can I run a distilled skill? _(Preview)_

Not automatically — skill *execution* is **dry-run planning only** and gated off by default (`SKILL_EXECUTION_ENABLED=false`). The intended path is to **download** a published skill's `SKILL.md` package and load it into your agent like any other Agent Skill. NAMS handles distillation, review, and publishing; running the procedure is the agent's job. See xref:reference/skills-api.adoc[Skills API].

[[neo4j-versions]]
=== Which Neo4j versions are supported?

Neo4j 5.x is supported, with **5.11+ recommended** for vector index support (used for semantic search).


[[aws-support]]
=== Does neo4j-agent-memory work with AWS?

Yes. The package provides full AWS support including:

* *Amazon Bedrock Embeddings* — Use Bedrock embedding models (Titan, Cohere) instead of OpenAI. Install with `pip install neo4j-agent-memory[bedrock]`.
* *Strands Agents SDK* — Pre-built tools for context graph operations with the AWS Strands Agents framework. Install with `pip install neo4j-agent-memory[strands]`.
* *AgentCore Memory* — `HybridMemoryProvider` for routing between short-term and long-term memory stores.

See xref:how-to/integrations/aws-strands.adoc[Strands Integration] and xref:how-to/integrations/aws-bedrock-embeddings.adoc[Bedrock Embeddings] for details.

[[bedrock-credentials]]
=== How do I configure AWS credentials for Bedrock embeddings?

The Bedrock embedder uses standard AWS credential resolution (environment variables, `~/.aws/credentials`, IAM roles). You can configure the region and profile:

[source,bash]
----
# Via environment variables
export NAM_EMBEDDING__PROVIDER=bedrock
export NAM_EMBEDDING__AWS_REGION=us-east-1
export NAM_EMBEDDING__AWS_PROFILE=my-profile
----

Or in Python:

[source,python]
----
from neo4j_agent_memory import MemorySettings

settings = MemorySettings(
    embedding={"provider": "bedrock", "aws_region": "us-east-1"}
)
----

No API keys are needed if you're running on an AWS resource with an appropriate IAM role.

[[strands-vs-direct]]
=== Should I use Strands tools or the MemoryClient directly?

Use **Strands tools** (`context_graph_tools()`) when building agents with the AWS Strands Agents SDK -- the tools are designed to be called by the agent autonomously.

Use the **MemoryClient directly** when you need programmatic control over memory operations outside of an agent loop, or when using a non-Strands framework.

You can combine both: use Strands tools for agent-facing operations and the MemoryClient for background tasks like batch processing.

== Entity Extraction Pipeline

[[how-pipeline-works]]
=== How does the extraction pipeline work?

The pipeline runs multiple extractors in sequence and merges their results:

[source]
----
Text → [spaCy] → [GLiNER2.5] → [LLM] → Merge → Validate relations → Results
----

[cols="1,2,1"]
|===
|Stage |Purpose |Speed

|**spaCy**
|Statistical NER for common entity types
|~1ms

|**GLiNER2.5**
|Zero-shot joint entity + relation decoding against the ontology
|~600ms (CPU, base-v1)

|**LLM**
|Context-aware extraction for complex cases
|~500ms
|===

Each stage is optional and configurable. See xref:how-to/entity-extraction.adoc[Entity Extraction] for details.

[[single-extractor]]
=== Can I use just one extractor instead of the full pipeline?

Yes, you can use any extractor individually:

[source,python]
----
from neo4j_agent_memory.extraction import (
    SpacyEntityExtractor,
    GLiNER2Extractor,
    LLMEntityExtractor,
)

# Just spaCy
extractor = SpacyEntityExtractor()

# Just GLiNER2.5
extractor = GLiNER2Extractor.for_schema("podcast")

# Just LLM
extractor = LLMEntityExtractor(model="gpt-4o-mini")

result = await extractor.extract("Your text here")
----

[[merge-strategies]]
=== What are merge strategies?

When using multiple extractors, you need to combine their results. Available strategies:

[cols="1,3"]
|===
|Strategy |Description

|`union`
|Keep all unique entities from all stages

|`intersection`
|Only keep entities found by multiple extractors

|`confidence`
|Keep highest confidence result per entity (default)

|`cascade`
|Use first extractor's results, fill gaps with others

|`first_success`
|Stop at first stage that returns results
|===

[[which-extractor]]
=== Which extractor should I use?

[cols="2,3"]
|===
|Use Case |Recommended Extractor

|Fast, basic NER (names, orgs, places)
|spaCy alone

|Domain-specific extraction
|GLiNER2.5 with a domain template

|Custom entity types without training
|GLiNER2.5 with your own ontology

|Complex text with context
|Full pipeline with LLM fallback

|Typed relationship extraction
|GLiNER2.5 on an ontology that declares relationships

|Cost-sensitive applications
|spaCy + GLiNER2.5 (no LLM)
|===


== GLiNER2.5 and Domain Schemas

[[schemas-gliner-only]]
=== Are domain schemas only used with GLiNER2.5?

Domain schemas are read most fully by GLiNER2.5, but since 0.7 the LLM stage also reads the ontology they convert into.

[cols="1,3"]
|===
|Extractor |Schema Support

|**spaCy**
|Uses a fixed set of trained entity types (PERSON, ORG, GPE, etc.). An ontology can only rename spaCy's labels onto POLE+O types and subtypes, not change what the model finds.

|**LLM**
|When an ontology is configured, the prompt carries its annotation guidelines and the legal `SOURCE -[REL]-> TARGET` catalogue.

|**GLiNER2.5**
|Compiles the ontology into a JointIE schema: descriptions become annotation guidelines and declared relationships constrain decoding.
|===

[[labels-vs-schemas]]
=== What's the difference between entity labels and domain schemas?

**Entity labels** are simple strings:

[source,python]
----
extractor = GLiNER2Extractor(entity_labels=["person", "company"])
----

**Domain schemas** include descriptions that help GLiNER2.5 understand what to extract:

[source,python]
----
# Schema includes detailed descriptions
extractor = GLiNER2Extractor.for_schema("podcast")
# {"person": "A person mentioned in the podcast, including hosts, guests...", ...}
----

Domain schemas significantly improve extraction accuracy, especially for ambiguous terms.

[[schemas-with-pipeline]]
=== Can I use domain schemas with the full pipeline?

Yes, when using the `ExtractorBuilder`, the schema applies to the GLiNER2.5 stage:

[source,python]
----
extractor = (
    ExtractorBuilder()
    .with_spacy()                              # Uses spaCy's built-in types
    .with_gliner_schema("podcast", threshold=0.5)  # Uses podcast schema
    .with_llm_fallback()                       # Gets the same ontology
    .merge_by_confidence()
    .build()
)
----

[[which-schema]]
=== Which schema should I use?

[cols="2,1"]
|===
|Content Type |Schema

|General purpose, investigations
|`poleo`

|Podcast transcripts, interviews
|`podcast`

|News articles, press releases
|`news`

|Research papers, academic content
|`scientific`

|Business reports, earnings calls
|`business`

|Movie/TV reviews, entertainment news
|`entertainment`

|Clinical notes, medical literature
|`medical`

|Legal documents, court cases
|`legal`
|===

[[custom-schemas]]
=== Can I create custom schemas?

Yes, create a `DomainSchema` with your entity types and descriptions:

[source,python]
----
from neo4j_agent_memory.extraction.domain_schemas import DomainSchema

my_schema = DomainSchema(
    name="real_estate",
    entity_types={
        "property": "A real estate property, building, or land parcel",
        "agent": "A real estate agent or broker",
        "price": "A property price, asking price, or sale price",
        "neighborhood": "A neighborhood, district, or area",
    },
)

extractor = GLiNER2Extractor(ontology=my_schema)
----

The `ontology=` argument accepts anything with a `to_ontology()` method, so a
`DomainSchema` or an `EntitySchemaConfig` works directly.

See xref:how-to/entity-extraction.adoc#custom-schemas[Creating Custom Schemas] for more examples.

[[poleo-mapping]]
=== Do schema entity types map to POLE+O types?

Yes, extracted labels are automatically mapped to POLE+O types for Neo4j storage:

* `person`, `author`, `actor`, `director` → `PERSON`
* `company`, `organization`, `institution` → `ORGANIZATION`
* `location`, `city`, `country` → `LOCATION`
* `event`, `meeting`, `case` → `EVENT`
* Everything else → `OBJECT` (with subtype from the label)

The ontology's own labels win, with `DEFAULT_LABEL_MAPPING` underneath as the
fallback. To override the table outright, pass `label_mapping=`:

[source,python]
----
from neo4j_agent_memory.extraction import DEFAULT_LABEL_MAPPING, GLiNER2Extractor

extractor = GLiNER2Extractor(
    entity_labels=["podcast_episode"],
    label_mapping={**DEFAULT_LABEL_MAPPING, "podcast_episode": ("EVENT", "PODCAST_EPISODE")},
)
----

== LLM Extraction

[[when-use-llm]]
=== When should I use the LLM extractor?

Use LLM extraction when you need:

* *Relationship extraction* — LLM is the only extractor that can extract relationships between entities
* *Complex context* — When entity identification requires understanding context
* *Highest accuracy* — When cost is not a concern

[[llm-models]]
=== What LLM models are supported?

Any OpenAI-compatible model:

* `gpt-4o-mini` (recommended for cost/performance balance)
* `gpt-4o` (highest accuracy)
* `gpt-3.5-turbo` (faster, cheaper)

[[local-llms]]
=== Can I use local LLMs?

The current implementation uses OpenAI's API. For local LLMs, you would need to:

. Run a local server with OpenAI-compatible API (e.g., using Ollama, vLLM)
. Point the `OPENAI_BASE_URL` environment variable to your local server

[[llm-slow]]
=== Why is LLM extraction slow?

LLM extraction requires an API call to the language model provider, which adds network latency (~200-500ms).

For high-throughput scenarios, consider:

* Using spaCy + GLiNER2.5 without LLM fallback
* Batching texts and processing in parallel
* Using a faster model like `gpt-3.5-turbo`


== Batch and Streaming Extraction

[[batch-extraction]]
=== How do I process multiple documents at once?

Use the batch extraction API:

[source,python]
----
from neo4j_agent_memory.extraction import ExtractionPipeline

pipeline = ExtractionPipeline()

# Extract from multiple texts in parallel
results = await pipeline.extract_batch(
    texts=["Document 1...", "Document 2...", "Document 3..."],
    batch_size=10,           # Process 10 at a time
    on_progress=lambda done, total: print(f"{done}/{total}"),
)
----

Benefits:
* Parallel processing with configurable concurrency
* Progress tracking callback
* `GLiNER2Extractor.extract_batch()` decodes a slice of texts in one forward pass

[[streaming-extraction]]
=== How do I handle very long documents?

Use streaming extraction for documents over 100K tokens:

[source,python]
----
from neo4j_agent_memory.extraction import StreamingExtractor

extractor = StreamingExtractor(
    chunk_size=4000,      # Tokens per chunk
    chunk_overlap=200,    # Overlap to preserve context
)

# Stream results as they're extracted
async for partial_result in extractor.stream(long_document):
    print(f"Found {len(partial_result.entities)} entities in chunk")

# Or get all results with automatic deduplication
result = await extractor.extract(long_document)
----

[[relation-extraction-llm-free]]
=== Can I extract relationships without LLM calls?

Yes. GLiNER2.5 decodes entities and relations in one pass, so relations come for
free with the extraction you already run:

[source,python]
----
from neo4j_agent_memory.extraction import ExtractorBuilder

extractor = (
    ExtractorBuilder()
    .with_gliner_schema("podcast")   # podcast declares WORKS_AT, FOUNDED, ...
    .build()
)

result = await extractor.extract(text)
# result.relations populated without LLM calls
----

Relations are only decoded when the ontology declares relationship types. The
`poleo`, `podcast` and `news` templates do; the other five are entity-only until
you attach relationships. Use `.with_ontology(doc).with_gliner()` for your own.

The separate GLiREL model was removed in 0.7 -- see
xref:how-to/migrate-to-gliner2.adoc[Migrate to GLiNER2.5].


== Entity Resolution and Deduplication

[[what-is-resolution]]
=== What is entity resolution?

Entity resolution identifies when different text mentions refer to the same entity. For example, "John Smith", "J. Smith", and "John" might all refer to the same person.

[[resolution-strategies]]
=== What resolution strategies are available?

[cols="1,3,2"]
|===
|Strategy |Description |Best For

|`exact`
|Case-insensitive string match
|Exact duplicates

|`fuzzy`
|RapidFuzz similarity matching
|Typos, abbreviations

|`semantic`
|Embedding-based similarity
|Synonyms, paraphrases

|`composite`
|Tries exact → fuzzy → semantic
|General use (default)
|===

[[resolution-type-aware]]
=== Is resolution type-aware?

Yes, the `CompositeResolver` is type-aware. Entities of different types (e.g., a PERSON named "Paris" vs a LOCATION named "Paris") are never merged, even if they have identical names.

[[deduplication-on-ingest]]
=== How does entity deduplication on ingest work?

Entity deduplication automatically merges similar entities during extraction:

[source,python]
----
from neo4j_agent_memory.memory.long_term import (
    DeduplicationConfig,
    LongTermMemory,
)

# Deduplication is configured at the memory layer, not on MemorySettings.
dedup_config = DeduplicationConfig(
    enabled=True,
    auto_merge_threshold=0.95,    # High similarity = auto-merge
    flag_threshold=0.85,          # Medium similarity = flagged SAME_AS link
    use_fuzzy_matching=True,
)

# Pass into LongTermMemory when constructing it manually, or rely on the
# defaults when using MemoryClient.
----

* **High confidence matches** (>0.92) are automatically merged
* **Medium confidence matches** (0.85-0.92) create `SAME_AS` relationships for manual review
* **Type-aware** -- only compares entities of the same type

[[same-as-relationships]]
=== What are SAME_AS relationships?

`SAME_AS` relationships link entities that may refer to the same real-world entity but weren't merged automatically due to lower confidence:

[source,cypher]
----
// Find potential duplicates
MATCH (e1:Entity)-[r:SAME_AS]->(e2:Entity)
RETURN e1.name, e2.name, r.confidence
ORDER BY r.confidence DESC
----

You can manually merge or keep them separate based on your domain knowledge.


== Neo4j and Storage

[[indexes]]
=== What indexes does the package create?

The package automatically creates:

* Unique constraints on ID fields
* Vector indexes for semantic search (requires Neo4j 5.11+)
* Regular indexes on frequently queried properties
* Point index on `Entity.location` for geospatial queries

[[entity-labels]]
=== How are entities labeled in Neo4j?

Entities get multiple labels based on their type:

* *Base label* — `:Entity`
* *Type label* — `:Person`, `:Organization`, `:Location`, `:Event`, `:Object`
* *Subtype label* — `:Vehicle`, `:Address`, `:Company`, etc. (if specified)

.Example
====
An entity of type `OBJECT` with subtype `VEHICLE` gets labels: `:Entity:Object:Vehicle`
====

[[query-by-type]]
=== Can I query entities by type directly?

Yes, the type labels enable efficient Cypher queries:

[source,cypher]
----
// Find all people
MATCH (p:Person) RETURN p

// Find all vehicles
MATCH (v:Vehicle) RETURN v

// Find organizations in a specific location
MATCH (o:Organization)-[:LOCATED_IN]->(l:Location {name: "New York"})
RETURN o
----

== Geocoding and Geospatial Queries

[[geocoding-enable]]
=== How do I enable geocoding for LOCATION entities?

Configure geocoding in your settings:

[source,python]
----
from neo4j_agent_memory import (
    MemorySettings,
    GeocodingConfig,
    GeocodingProvider,
)

settings = MemorySettings(
    geocoding=GeocodingConfig(
        enabled=True,
        provider=GeocodingProvider.NOMINATIM,  # Free, 1 req/sec limit
    )
)
----

Or use environment variables:

[source,bash]
----
NAM_GEOCODING__ENABLED=true
NAM_GEOCODING__PROVIDER=nominatim
----

[[geocoding-providers]]
=== What geocoding providers are supported?

[cols="1,2,2"]
|===
|Provider |Pros |Cons

|**Nominatim**
|Free, no API key needed
|Rate-limited to 1 request/second

|**Google Maps**
|Higher accuracy, better address parsing
|Requires API key, pay-per-use
|===

For Google Maps:

[source,python]
----
from pydantic import SecretStr

settings = MemorySettings(
    geocoding=GeocodingConfig(
        enabled=True,
        provider=GeocodingProvider.GOOGLE,
        api_key=SecretStr("your-google-api-key"),
    )
)
----

[[geocoding-batch]]
=== How do I geocode existing locations?

Use the batch geocoding method for LOCATION entities without coordinates:

[source,python]
----
async with MemoryClient(settings) as memory:
    stats = await memory.long_term.geocode_locations(
        batch_size=50,
        skip_existing=True,  # Don't re-geocode
    )
    print(f"Geocoded {stats['geocoded']} of {stats['processed']} locations")
----

[[geospatial-queries]]
=== What geospatial queries are supported?

Once locations are geocoded, you can:

[source,python]
----
# Find locations near a point
nearby = await memory.long_term.search_locations_near(
    latitude=40.7128,
    longitude=-74.0060,
    radius_km=10.0,
    limit=20,
)

# Find locations within a bounding box
in_area = await memory.long_term.search_locations_in_bounds(
    min_lat=40.70,
    max_lat=40.80,
    min_lon=-74.02,
    max_lon=-73.95,
)

# Get coordinates for a specific location
coords = await memory.long_term.get_entity_coordinates(entity_id)
----

[[geocoding-skip]]
=== Can I disable geocoding for specific entities?

Yes, use the `geocode=False` parameter:

[source,python]
----
entity, _ = await memory.long_term.add_entity(
    name="Custom Location",
    entity_type="LOCATION",
    geocode=False,  # Skip geocoding
    coordinates=(40.7128, -74.0060),  # Provide coordinates directly
)
----

# For OpenTelemetry
pip install neo4j-agent-memory[opentelemetry]

from neo4j_agent_memory.observability import get_tracer

# Observability tracers are obtained from

tracer = get_tracer(

[[what-is-traced]]
=== What operations are traced?

With tracing enabled, you get visibility into:

* **Memory operations** -- reads, writes, searches with timing
* **Extraction pipeline** -- each stage (spaCy, GLiNER2.5, LLM) with duration
* **LLM calls** -- tokens, latency, costs
* **Entity resolution** -- matches, merges, SAME_AS creation

== Performance and Optimization

[[speed-up-extraction]]
=== How can I speed up extraction?

. **Disable unused extractors**:
+
[source,python]
----
config = ExtractionConfig(
    enable_spacy=True,
    enable_gliner=True,
    enable_llm_fallback=False,  # Skip LLM
)
----

. **Use GPU acceleration for GLiNER2.5**:
+
[source,python]
----
extractor = GLiNER2Extractor(device="cuda")  # or "mps" for Mac
----

. **Use batch extraction for multiple documents**:
+
[source,python]
----
results = await pipeline.extract_batch(texts, batch_size=10)
----

. **Let GLiNER2.5 do the relations instead of the LLM**:
+
[source,python]
----
extractor = ExtractorBuilder().with_gliner_schema("podcast").build()
----

. **Use a smaller GLiNER2.5 checkpoint**:
+
[source,python]
----
extractor = GLiNER2Extractor(model="fastino/gliner2.5-small-v1")
----
+
Or trade precision for speed with `quantize=True` (fp16) and `compile=True`
(`torch.compile`).

[[caching]]
=== Can I cache extraction results?

The package doesn't include built-in caching, but you can implement it:

[source,python]
----
import hashlib
from functools import lru_cache

@lru_cache(maxsize=1000)
async def cached_extract(text_hash: str, text: str):
    return await extractor.extract(text)

# Use hash as cache key
text_hash = hashlib.md5(text.encode()).hexdigest()
result = await cached_extract(text_hash, text)
----


== Troubleshooting

[[gliner-download-fails]]
=== GLiNER2.5 model download fails

If the model download fails, try:

. Check your internet connection
. Set `HF_HUB_OFFLINE=0` to allow downloads
. Manually download from HuggingFace and pass the local path as `model=`

A `ValueError` naming a "GLiNER v1 checkpoint" is a different problem: the id
you passed (`urchade/...`, `gliner-community/...`, `numind/...`) is from the
removed v1 stack. Use `fastino/gliner2.5-base-v1` -- see
xref:how-to/migrate-to-gliner2.adoc[Migrate to GLiNER2.5].

[[spacy-model-not-found]]
=== spaCy model not found

Install the model:

[source,bash]
----
python -m spacy download en_core_web_sm
----

[[low-accuracy]]
=== Low extraction accuracy

. **Use the right schema** -- Domain schemas significantly improve accuracy
. **Lower the threshold** -- Try `threshold=0.3` instead of `0.5`
. **Check for noise** -- Filter results with `result.filter_invalid_entities()`
. **Consider LLM fallback** -- Enable for complex texts

[[filtered-incorrectly]]
=== Entities being filtered incorrectly

Check if your entity is in the stopword list:

[source,python]
----
from neo4j_agent_memory.extraction import is_valid_entity_name, ENTITY_STOPWORDS

is_valid_entity_name("your entity")  # Check if it passes
print("they" in ENTITY_STOPWORDS)    # Check specific word
----

[[memory-errors]]
=== Memory errors with large texts

GLiNER2.5 trains on sequences up to 4,096 words, but *relation* recall
collapses past roughly 400 words -- often to zero, with no error. The extractor
therefore windows anything longer than `max_words` (384) automatically, and
relations whose endpoints land in different windows are lost. For large texts:

. Extract per message or per document section rather than per concatenation
. Use `StreamingExtractor` when you want chunk-level results and progress
. Merge and deduplicate results

A related symptom is an empty result with a `RuntimeWarning` about
`feasible=False`: that means the decoder could not satisfy the ontology's hard
constraints (uniqueness, acyclicity), *not* that the text had no entities.

[[extra-forbidden-from-env]]
=== Why does `MemorySettings(...)` raise `extra_forbidden` for `neo4j_uri` / `openai_api_key`?

You see an error like:

[source,text]
----
ValidationError: 1 validation error for MemorySettings
neo4j_uri
  Extra inputs are not permitted [type=extra_forbidden, input_value='neo4j://localhost:7687']
----

…even though you only passed `neo4j={...}` as a kwarg. The cause is unrelated keys in your `.env` file (e.g. plain `NEO4J_URI=...` from a Docker setup, or `OPENAI_API_KEY=...` for a different tool). pydantic-settings 2.x leaks unmatched `.env` keys into the validation payload regardless of `env_prefix`, and `MemorySettings` uses `extra="forbid"` to catch code-level typos.

**Fix:** upgrade to the next `0.2.x` patch release of `neo4j-agent-memory` (not `0.2.0`) or later -- `MemorySettings` filters non-`NAM_`-matching keys before they reach validation. No code change needed.

**On older versions:** subclass `MemorySettings` (or your own settings class) with `extra="ignore"`:

[source,python]
----
from pydantic_settings import SettingsConfigDict
from neo4j_agent_memory import MemorySettings

class MySettings(MemorySettings):
    model_config = SettingsConfigDict(
        env_prefix="NAM_",
        env_nested_delimiter="__",
        env_file=".env",
        env_file_encoding="utf-8",
        extra="ignore",
    )
----

[[gliner-not-installed]]
=== ImportError: GLiNER2.5 not installed

GLiNER2.5 is an optional dependency. Install with:

[source,bash]
----
pip install "neo4j-agent-memory[gliner2]"
# or
uv sync --all-extras
----

The `[extraction]` and `[full]` extras include it too. `[gliner]` still works as
a deprecated alias of `[gliner2]` and is removed in 0.8.

Check availability in code:

[source,python]
----
from neo4j_agent_memory.extraction import GLiNER2Extractor, is_gliner2_available

if is_gliner2_available():
    extractor = GLiNER2Extractor.for_schema("podcast")
else:
    print("GLiNER2.5 not available, using spaCy only")
    extractor = SpacyEntityExtractor()
----

Importing one of the names removed in 0.7 (`GLiNEREntityExtractor`,
`GLiRELExtractor`, `GLiNERWithRelationsExtractor`, `is_gliner_available`,
`is_glirel_available`, `DEFAULT_RELATION_TYPES`) raises an `ImportError` that
names its replacement.
