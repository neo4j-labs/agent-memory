= Extractor classes reference
:page-product: agent-memory
:page-pagination:
:toclevels: 2

Local Python extraction classes and result models. They can be used independently or injected into a bolt MemoryClient; they do not configure the hosted NAMS pipeline.

Signatures below show types, keyword-only arguments (`*`), and defaults. They are reference declarations; the examples show calls to execute.

See xref:reference/backend-capabilities.adoc[Backend capabilities] for availability and data scope.

== EntityExtractor protocol

The protocol requires `extract`, not `extract_batch`. Batch methods are concrete capabilities with different signatures on GLiNER and ExtractionPipeline; check the selected class.

// contract: extraction/base.py:EntityExtractor.extract
[source,python]
----
async def extract(
    text: str,
    *,
    entity_types: list[str] | None=None,
    extract_relations: bool=True,
    extract_preferences: bool=True,
) -> ExtractionResult: ...
----

== Result models

These are Pydantic models imported from `neo4j_agent_memory.extraction`. `ExtractedEntity` uses `type` and `attributes`, not `entity_type` and `metadata`. ExtractionResult has entities, relations, preferences, and source_text; it has no metadata envelope.

Fields and defaults:

[cols="1,2,1,3",options="header"]
|===
| Field | Type | Default | Description
| `category` | `str` | `required` | Preference category
| `preference` | `str` | `required` | The preference statement
| `context` | `str \| None` | `None` | Context where preference applies

`ExtractionResult.entity_count`, `relation_count`, and `preference_count` are properties. `entities_by_type()` groups entities into a dictionary; `get_entities_of_type(type)` returns a list using case-insensitive type matching. `filter_invalid_entities()` returns a new result with invalid names and affected relations removed. There are no `filter_by_type` or `filter_by_confidence` methods.

[source,python]
----
people = result.get_entities_of_type("PERSON")
high_confidence = [entity for entity in result.entities if entity.confidence >= 0.7]
print(result.entities_by_type())
----

`ExtractedEntity.normalized_name` lowercases/normalizes its name and `full_type` includes its subtype. `ExtractedRelation.as_triple` returns source, relation type, and target.

== SpacyEntityExtractor

Statistical NER using a separately installed spaCy model. Import from `neo4j_agent_memory.extraction`. Install the matching extraction extra and model before running inference.

// contract: extraction/spacy_extractor.py:SpacyEntityExtractor.__init__
[source,python]
----
def SpacyEntityExtractor(
    model: str='en_core_web_sm',
    type_mapping: dict[str, str] | None=None,
    subtype_mapping: dict[str, str] | None=None,
    default_confidence: float=0.85,
    context_window: int=50,
): ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `model` | spaCy model name (e.g., "en_core_web_sm", "en_core_web_lg")
| `type_mapping` | Custom mapping from spaCy labels to POLE+O types
| `subtype_mapping` | Custom mapping from spaCy labels to subtypes
| `default_confidence` | Default confidence score (spaCy doesn't provide per-entity scores)
| `context_window` | Number of characters of context to include around entities
|===

The default mappings include PERSON → PERSON, ORG → ORGANIZATION, GPE/LOC → LOCATION, EVENT → EVENT, and PRODUCT/WORK_OF_ART → OBJECT. Subtype mappings are retained on results. Override the mapping explicitly for your domain.

[source,python]
----
from neo4j_agent_memory.extraction import SpacyEntityExtractor

extractor = SpacyEntityExtractor(model="en_core_web_sm")
result = await extractor.extract("John works at Apple in California")
----

== GLiNEREntityExtractor

Zero-shot entity extraction with labels or domain descriptions. The constructor accepts a DomainSchema object; use `for_schema(name)` for a built-in schema name. Models load lazily when inference is requested.

// contract: extraction/gliner_extractor.py:GLiNEREntityExtractor.__init__
[source,python]
----
def GLiNEREntityExtractor(
    model: str=DEFAULT_GLINER2_MODEL,
    entity_labels: list[str] | dict[str, str] | None=None,
    threshold: float=0.5,
    flat_ner: bool=True,
    multi_label: bool=False,
    device: str='cpu',
    context_window: int=50,
    label_mapping: dict[str, tuple[str, str | None]] | None=None,
    schema: DomainSchema | None=None,
): ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `model` | GLiNER model name from HuggingFace (default: gliner-community/gliner_medium-v2.5)
| `entity_labels` | Entity labels (list) or labels with descriptions (dict). Descriptions improve extraction accuracy with GLiNER2.
| `threshold` | Confidence threshold for including entities (0.0-1.0)
| `flat_ner` | Use flat NER (no nested entities)
| `multi_label` | Allow multiple labels per entity
| `device` | Device to run on (cpu, cuda, mps)
| `context_window` | Characters of context to include around entities
| `label_mapping` | Custom mapping from GLiNER labels to (TYPE, SUBTYPE)
| `schema` | Pre-defined DomainSchema to use (overrides entity_labels)
|===

== ExtractionPipeline

Run stages and merge their results. Import the direct `MergeStrategy` from `neo4j_agent_memory.extraction.pipeline`. Its values are distinct from the smaller settings enum.

// contract: extraction/pipeline.py:ExtractionPipeline.__init__
[source,python]
----
def ExtractionPipeline(
    stages: list[ExtractionStage | EntityExtractor],
    merge_strategy: MergeStrategy=MergeStrategy.CONFIDENCE,
    stop_on_success: bool=False,
    min_entities_for_success: int=1,
    fallback_on_error: bool=True,
): ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `stages` | List of extraction stages or extractors to run
| `merge_strategy` | Strategy for merging results from stages
| `stop_on_success` | Stop after first stage that returns entities
| `min_entities_for_success` | Minimum entities to consider a stage successful
| `fallback_on_error` | Continue to next stage if current stage errors
|===

[cols="1,3",options="header"]
|===
| Strategy | Behavior
| `UNION` | Keep unique entities across results.
| `INTERSECTION` | Keep entities found by multiple results.
| `CONFIDENCE` | Keep the highest-confidence entity for each matching name/type.
| `CASCADE` | Keep earlier-stage entities and fill gaps from later results.
| `FIRST_SUCCESS` | Stop after a stage reaches min_entities_for_success and return the first nonempty successful result.
|===

`stop_on_success=True` also enables early stopping with the other merge strategies. `FIRST_SUCCESS` is not `FIRST` or `LAST`, and cannot be selected through the config.settings MergeStrategy enum.

[source,python]
----
from neo4j_agent_memory.extraction import ExtractionPipeline, SpacyEntityExtractor, GLiNEREntityExtractor
from neo4j_agent_memory.extraction.pipeline import MergeStrategy

pipeline = ExtractionPipeline(
    stages=[SpacyEntityExtractor(), GLiNEREntityExtractor.for_schema("podcast")],
    merge_strategy=MergeStrategy.CONFIDENCE,
)
result = await pipeline.extract("John discussed Acme in the podcast")
----

== ExtractorBuilder

Build a local extractor from enabled stages. `build()` returns NoOpExtractor when no stage is enabled, the concrete extractor for one stage, or ExtractionPipeline for multiple stages.

[source,python]
----
from neo4j_agent_memory.extraction import ExtractorBuilder

extractor = (
    ExtractorBuilder()
    .with_spacy("en_core_web_sm")
    .with_gliner_schema("podcast", threshold=0.5)
    .with_llm_fallback("gpt-4o-mini")
    .merge_by_confidence()
    .build()
)
----

The union method is `merge_by_union()`. `with_schema(EntitySchemaConfig)` copies entity type names into extraction labels; it does not apply relation endpoints, properties, constraints, or indexes. Use the explicit schema/validation APIs for those purposes.

== StreamingExtractor

Chunk long documents and combine extraction results. Import from `neo4j_agent_memory.extraction`. `DEFAULT_CHUNK_SIZE` is 4000 characters and `DEFAULT_OVERLAP` is 200, unless token-based chunking is selected.

|===
| Parameter | Description
