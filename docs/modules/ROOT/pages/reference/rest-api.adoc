= REST API reference
:description: Hosted-service REST endpoints mapped to client SDK methods in each language.

The hosted service at `+https://memory.neo4jlabs.com/v1+` exposes a REST API.
This page is a curated companion to the machine-readable contract — it maps
selected endpoints to protocol operation names and client accessors. A protocol operation is not necessarily exposed as a public method in every SDK.

[TIP]
====
The *authoritative, always-current contract* is the OpenAPI document at
link:https://memory.neo4jlabs.com/openapi.json[memory.neo4jlabs.com/openapi.json]
(production). Request/response schemas live there; this page covers the
cross-cutting rules — auth, versioning, errors, pagination — and the
SDK-method mapping the spec doesn't show.
====

The protocol-operation column uses conformance names from the link:https://github.com/neo4j-labs/agent-memory-tck[agent-memory-tck]
cross-language conformance suite. Check the client accessor column rather than converting a protocol name to another casing. Python endpoint registry names can differ (for example, its message-list route uses `list_messages`, while its public method is `short_term.get_conversation`).

== Base URL and protocol version

NAMS is an unversioned, continuously shipped service. `/v1` identifies its REST protocol; it is independent of Python/TypeScript package versions. The production base URL is `+https://memory.neo4jlabs.com/v1+`. The SDK appends paths to the configured
`MEMORY_ENDPOINT` (default the URL above). The `/v\{n}` prefix also selects the
REST transport; endpoints without it use the TCK bridge protocol (see
xref:explanation/backends.adoc[Bolt vs NAMS]).

[NOTE]
====
The active workspace is resolved from the API key (and/or the `X-Workspace-Id`
header), not from the URL path — so endpoints like read-only Cypher are
`POST /v1/query`, scoped to the caller's workspace. Treat
link:https://memory.neo4jlabs.com/openapi.json[the OpenAPI spec] as the source of
truth for exact paths, and prefer the SDK accessors (e.g. `client.query.cypher(...)`)
over hand-built URLs.
====

== Request headers

Every request carries `Authorization: Bearer <token>`, where the token is either
your API key (`nams_...`) used directly, or a short-lived JWT obtained from the
Auth0 exchange endpoints (`POST /v1/auth/exchange`, `POST /v1/auth/refresh`).

The target workspace depends on the key's category (see
xref:reference/authentication.adoc[Authentication & API Keys]): a **workspace
key** is already bound to one workspace, so `X-Workspace-Id` is optional (and a
_different_ value is rejected with `403`); an **admin key** names the workspace
per request with `X-Workspace-Id: <workspace_id>`. The SDK sends the header
automatically when `workspace_id` / `workspaceId` (or `MEMORY_WORKSPACE_ID`) is
configured. Python's default transport sends its configured API key directly; calling a token-refresh wrapper does not install automatic token refresh. See xref:how-to/use-nams.adoc[Use NAMS].

On Python, `get_conversation` makes both metadata and message requests. There is no public `get_conversation_metadata` or `delete_conversation`; use `clear_session` for whole-conversation deletion.

[#auto-merged-entity-creates]
=== Auto-merged entity creates

When `POST /entities` resolves a name to an existing entity, it returns a
`resolution: "merged"` envelope instead of a complete entity. Python
`add_entity` and TypeScript `addEntity` fetch the canonical entity and return it.
Both expose the create operation's resolution in `entity.metadata` under the
reserved `nams_resolution` key, preserving other entity metadata:

[source,json]
----
{
  "nams_resolution": {
    "resolution": "merged",
    "merged_into": "00000000-0000-0000-0000-000000000001",
    "merge_confidence": 0.93,
    "fallback": false
  }
}
----

`merge_confidence` is the service's name-match score and is omitted when absent
or null. It does not replace the canonical entity's own `confidence`.

If the canonical GET returns 404, an empty body, or an incomplete response
without a usable name, the SDK can return a fallback using the server-provided
merge ID and requested name/type. `fallback: true` identifies this result;
its creation timestamp is generated by the client, not read from the server.
Python uses its entity confidence default of `1.0`; TypeScript leaves entity
confidence undefined. These fallback values are not estimates of stored
canonical values. Missing merge IDs and malformed populated fields are
validation errors. Authentication, rate-limit, network, and server errors
propagate to the caller instead of returning a fallback.

Ordinary creates and `review_pending` responses return their entity directly
without a follow-up GET.

[#errors]
== Errors

Error responses use standard HTTP status codes with a JSON body of the shape
`{"error": "<message>"}`. Some errors carry extra fields (e.g. `message`,
`limit` on quota errors). The SDK maps them to typed exceptions:

[cols="1,2,2",options="header"]
|===
| Status | Meaning | Python SDK exception

| `400` | Invalid request, write Cypher attempted, validation failure | `ValidationError` (carries `details`)
| `401`, `403` | Missing/invalid token, or workspace not accessible | `AuthenticationError`
| `404` | Resource not found | `NotFoundError` (subclasses `MemoryError`)
| `405`, `501` | Operation not available on this backend | `NotSupportedError`
| `429` | Rate limited | `RateLimitError` (carries `retry_after`; honors `Retry-After`)
| `5xx` | Service error | `TransportError` (after retries exhausted)
| Other 4xx (e.g. `409`, `410`, `413`, `422`) | Conflict, gone, payload too large, semantic validation | `TransportError`
|===

All SDK exceptions subclass `MemoryError`. The Python transport retries `429`, `500`, `502`, `503`, `504`, and connection/timeout/remote-protocol errors with exponential backoff. It honors numeric `Retry-After` seconds; HTTP-date Retry-After values are not parsed. See xref:reference/nams-limits.adoc[NAMS Limits & Behavior]
for rate-limit and quota specifics.

The TypeScript REST transport reports 404 as `TransportError` with
`statusCode === 404`; its exported `NotFoundError` is not used by that transport.

== Pagination

Pagination is endpoint- and client-specific; inspect the OpenAPI schema for the endpoint you call. Python `short_term.list_conversations` forwards `limit` and `user_identifier` (as userId), but does not forward `offset`. Do not infer that an accepted `**kwargs` name becomes a request parameter. Other Python accessors may implement their own pagination controls. Pass supported limits explicitly when deterministic page sizes are needed.

== Wire format differences

* Hosted REST: camelCase fields (`userId`, `conversationId`, `createdAt`).
* Bridge protocol: snake_case fields (`user_id`, `conversation_id`,
  `created_at`).

The wrappers translate their supported fields; NAMS ontologies use snake_case request documents. Python may synthesize model fields where hosted responses do not carry bolt equivalents; see the API references. If you're writing a custom transport,
see the link:https://github.com/neo4j-labs/agent-memory-tck/blob/main/docs/reference/bridge-protocol.adoc[bridge-protocol reference]
and the language-specific `casing` modules in the TCK repo.
