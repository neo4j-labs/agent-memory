= Domain Schemas Reference
:page-product: agent-memory

Reference for built-in domain schemas and custom schema creation.

== Overview

Domain schemas define entity types with descriptions that improve GLiNER2.5 zero-shot extraction accuracy. Each schema is optimized for a specific domain.

A `DomainSchema` is a *catalog*: labels with descriptions, and no endpoint typing. `DomainSchema.to_ontology()` converts one into an `OntologyDocument`, which is what the extractor actually compiles. Each catalog also has a matching built-in ontology template of the same name (`neo4j_agent_memory.ontology.get_template`) — the same labels, with relationships attached where they exist.

The tables below are generated from `DOMAIN_SCHEMAS` in `neo4j_agent_memory.extraction.domain_schemas`; that module is the source of truth.

== Using Schemas

=== With GLiNER2Extractor

[source,python]
----
from neo4j_agent_memory.extraction import GLiNER2Extractor

# Use named schema
extractor = GLiNER2Extractor.for_schema("podcast")

# With custom threshold
extractor = GLiNER2Extractor.for_schema("medical", threshold=0.6)
----

`for_schema()` resolves the name through `neo4j_agent_memory.ontology.get_template`,
so the extractor gets the template's relationships as well as its labels.

=== With ExtractorBuilder

[source,python]
----
from neo4j_agent_memory.extraction import ExtractorBuilder

extractor = (
    ExtractorBuilder()
    .with_gliner_schema("news", threshold=0.5)
    .build()
)
----

=== Listing Available Schemas

[source,python]
----
from neo4j_agent_memory.extraction import list_schemas, get_schema

# List all schema names
print(list_schemas())
# ['poleo', 'podcast', 'news', 'scientific', 'business', 'entertainment', 'medical', 'legal']

# Get schema details
schema = get_schema("podcast")
for entity_type, description in schema.entity_types.items():
    print(f"{entity_type}: {description}")
----

=== Converting a Schema to an Ontology

[source,python]
----
from neo4j_agent_memory.extraction import get_schema
from neo4j_agent_memory.ontology import RelationshipDef

# Labels only
doc = get_schema("medical").to_ontology()

# Labels plus typed relationships
doc = get_schema("medical").to_ontology(
    relationships=[
        RelationshipDef(
            type="TREATS",
            source="drug",
            target="disease",
            description="A medication used to treat a condition",
        ),
    ],
)
----

Each `source` and `target` must name a label the schema declares. A relationship
with no description picks one up from `DomainSchema.relation_types` when it names
the same type.

== Creating Custom Schemas

=== DomainSchema Class

[source,python]
----
from neo4j_agent_memory.extraction.domain_schemas import DomainSchema

real_estate_schema = DomainSchema(
    name="real_estate",
    entity_types={
        "property": "A real estate property, building, or land parcel",
        "agent": "A real estate agent or broker",
        "buyer": "A property buyer or purchaser",
        "seller": "A property seller or owner",
        "price": "A property price, valuation, or asking price",
        "location": "A neighborhood, city, or street address",
    },
)

extractor = GLiNER2Extractor(ontology=real_estate_schema, threshold=0.5)
----

=== Schema Best Practices

1. **Use descriptive names**: `"A real estate property"` is better than `"property"`
2. **Include synonyms**: `"A company, startup, or business organization"`
3. **Be domain-specific**: Tailor descriptions to your use case
4. **Test thresholds**: Lower thresholds catch more entities but may reduce precision

== Schema Persistence

Store custom schemas in Neo4j for reuse:

[source,python]
----
from neo4j_agent_memory.schema import SchemaManager, EntitySchemaConfig, EntityTypeConfig

# Create schema config
config = EntitySchemaConfig(
    name="real_estate",
    version="1.0",
    description="Real estate domain schema",
    entity_types=[
        EntityTypeConfig(name="PROPERTY", description="A real estate property"),
        EntityTypeConfig(name="AGENT", description="A real estate agent"),
    ],
)

# Save to Neo4j
manager = SchemaManager(client.graph)
stored = await manager.save_schema(config, created_by="admin")

# Load later
schema = await manager.load_schema("real_estate")
----

== Entity Type Mapping

Map schema types to POLE+O for graph storage:

[cols="1,1,1", options="header"]
|===
| Schema Type | POLE+O Type | Neo4j Labels

| `PERSON`, `ACTOR`, `AUTHOR`
| `PERSON`
| `:Entity:Person`

| `COMPANY`, `ORGANIZATION`, `INSTITUTION`
| `ORGANIZATION`
| `:Entity:Organization`

| `LOCATION`, `CITY`, `COUNTRY`
| `LOCATION`
| `:Entity:Location`

| `EVENT`, `MEETING`, `INCIDENT`
| `EVENT`
| `:Entity:Event`

| `PRODUCT`, `OBJECT`, `VEHICLE`
| `OBJECT`
| `:Entity:Object`
|===

Custom types not in POLE+O are stored with `:Entity:\{CustomType\}` labels.

The lookup table is `DEFAULT_LABEL_MAPPING` in
`neo4j_agent_memory.extraction.label_mapping`; an ontology's own labels take
precedence over it, and anything unmatched lands on `OBJECT` with the label as
the subtype.
