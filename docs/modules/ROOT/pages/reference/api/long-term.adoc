= LongTermMemory API reference
:page-product: agent-memory
:page-pagination:
:toclevels: 2

Entity, preference, fact, relationship, provenance, and location operations exposed through `client.long_term`. The main signatures describe the bolt implementation; hosted differences are listed separately.

Signatures below show types, keyword-only arguments (`*`), and defaults. They are reference declarations; the examples show calls to execute.

See xref:reference/backend-capabilities.adoc[Backend capabilities] for availability and data scope.

== Overview

The default POLE+O entity types are `PERSON`, `OBJECT`, `LOCATION`, `EVENT`, and `ORGANIZATION`. Subtypes and custom types depend on the configured domain schema.

[source,python]
----
# Bolt: add_entity returns an entity and its deduplication result.
person, dedup = await client.long_term.add_entity(
    "John Smith", "PERSON", subtype="INDIVIDUAL"
)
company, _ = await client.long_term.add_entity(
    "Acme Corp", "ORGANIZATION", subtype="COMPANY"
)
await client.long_term.add_relationship(person, company, "WORKS_AT")
for entity in await client.long_term.search_entities("software company"):
    print(entity.name, entity.metadata.get("similarity"))
----

Search methods return models, not `(model, score)` tuples. Bolt semantic-search scores are stored in `metadata["similarity"]`. Entity search is not user-scoped; see the backend capability and scope reference before designing tenancy.

== Entity operations (bolt)

=== add_entity

On Bolt, entity writes merge by exact `(name, type)`, including when `deduplicate=False`. On an existing-node match, the current method can return a newly allocated ID instead of the persisted node ID. Before linking repeated entities, read the persisted ID with an exact name/type Cypher lookup and check that it resolves unambiguously. The xref:tutorials/knowledge-graph.adoc[document tutorial] includes this readback.

Add an entity and return `(Entity, DeduplicationResult)`. Geocoding and enrichment flags default to True, but run only when their providers are configured. There is no `confidence` keyword; `attributes` and `metadata` are distinct fields.

// contract: memory/long_term.py:LongTermMemory.add_entity
[source,python]
----
async def add_entity(
    name: str,
    entity_type: EntityType | str,
    *,
    subtype: str | None=None,
    description: str | None=None,
    aliases: list[str] | None=None,
    attributes: dict[str, Any] | None=None,
    resolve: bool=True,
    generate_embedding: bool=True,
    deduplicate: bool=True,
    geocode: bool=True,
    enrich: bool=True,
    coordinates: tuple[float, float] | None=None,
    metadata: dict[str, Any] | None=None,
) -> tuple[Entity, DeduplicationResult]: ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `name` | Entity name
| `entity_type` | Entity type (PERSON, OBJECT, LOCATION, EVENT, ORGANIZATION)
| `subtype` | Optional subtype (e.g., VEHICLE for OBJECT)
| `description` | Optional description
| `aliases` | Optional list of alternative names
| `attributes` | Optional additional attributes
| `resolve` | Whether to resolve against existing entities
| `generate_embedding` | Whether to generate embedding
| `deduplicate` | Whether to check for duplicate entities
| `geocode` | Whether to geocode LOCATION entities (requires geocoder)
| `enrich` | Whether to queue for background enrichment
| `coordinates` | Optional (latitude, longitude) tuple to set directly
| `metadata` | Optional metadata
|===

== Preference operations (bolt only)

=== add_preference

Store a preference. Use `preference`, not `value`, as the keyword. `user_identifier` creates an explicit user association; `applies_to` targets an entity.

// contract: memory/long_term.py:LongTermMemory.add_preference
[source,python]
----
async def add_preference(
    category: str,
    preference: str,
    *,
    context: str | None=None,
    confidence: float=1.0,
    generate_embedding: bool=True,
    metadata: dict[str, Any] | None=None,
    user_identifier: str | None=None,
    applies_to: list[Any] | None=None,
) -> Preference: ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `category` | Preference category (food, music, communication, etc.)
| `preference` | The preference statement
| `context` | When/where preference applies
| `confidence` | Confidence score
| `generate_embedding` | Whether to generate embedding
| `metadata` | Optional metadata
| `user_identifier` | When provided, writes a `(:User)-[:HAS_PREFERENCE]->(:Preference)` edge linking the preference to the user's :User node. Multi-tenant deployments should pass this on every call.
| `applies_to` | Optional list of `EntityRef` describing the entities this preference scopes to. Each ref is materialized as a `(:Preference)-[:APPLIES_TO]->(:Entity)` edge so `get_preferences_for(user, applies_to=...)` queries can find scoped preferences efficiently.
|===

== NAMS behavior

NAMS manages extraction and resolution on the server. These are the client wrapper differences, not service versions or pricing tiers.

[cols="1,3",options="header"]
|===
| Operation | Hosted behavior
| `add_entity` | Returns one `Entity`, not a deduplication tuple. Sends only name, type, and description. Bolt subtype, aliases, attributes, metadata, and provider-control kwargs are not sent.
| `search_entities` | Sends query, limit, and a single type via `entity_type` (aliases `type` and `label`). Bolt `entity_types`, `subtypes`, and `threshold` are not sent. Search is workspace-wide.
| `get_entity_by_name` | Searches up to 20 results and returns the first exact case-sensitive name match, or None.
| `get_related_entities` | Returns identifying relationship dictionaries (`relType`, `targetId`, `targetName`, `targetType`), not full Entity models. Traversal kwargs are not sent.
| `get_entity_relationships` | Adapts inline relationships into Relationship models. IDs and creation times are synthesized locally; they are not stable server relationship identities.
| `get_context` | Returns an empty string. Use entity search and conversation context explicitly.
| Preferences, facts, `add_relationship` | Raise `NotSupportedError`; no corresponding hosted public operation is provided by these wrappers.
| Deduplication administration, local geocoding, extractor registration/linking/statistics | Bolt-only methods; not exposed by `NamsLongTermMemory`.
|===

[source,python]
----
# NAMS: retain the entity directly; no tuple unpacking.
entity = await client.long_term.add_entity("Acme Corp", "ORGANIZATION")
----
