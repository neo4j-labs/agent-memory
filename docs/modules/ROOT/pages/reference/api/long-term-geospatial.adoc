== Geospatial operations (bolt only)

=== search_locations_near

Find Location entities within a radius of a point.

// contract: memory/long_term.py:LongTermMemory.search_locations_near
[source,python]
----
async def search_locations_near(
    latitude: float,
    longitude: float,
    *,
    radius_km: float=10.0,
    session_id: str | None=None,
    limit: int=10,
) -> list[Entity]: ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `latitude` | Latitude of the center point
| `longitude` | Longitude of the center point
| `radius_km` | Search radius in kilometers (default 10km)
| `session_id` | Optional session ID to filter locations by conversation
| `limit` | Maximum number of results
|===

=== geocode_locations

Batch geocode location entities without coordinates. Returns only `processed` and `geocoded` counts; without a configured geocoder both counts are zero.

// contract: memory/long_term.py:LongTermMemory.geocode_locations
[source,python]
----
async def geocode_locations(
    *,
    batch_size: int=50,
    skip_existing: bool=True,
    on_progress: Callable[[int, int], None] | None=None,
) -> dict[str, int]: ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `batch_size` | Number of locations to process per batch
| `skip_existing` | Skip locations that already have coordinates
| `on_progress` | Progress callback (processed_count, total_count)
|===

Although `skip_existing` is accepted, the current query always selects locations without coordinates. Passing False does not refresh previously geocoded locations.

== NAMS behavior

NAMS manages extraction and resolution on the server. These are the client wrapper differences, not service versions or pricing tiers.

[cols="1,3",options="header"]
|===
| Operation | Hosted behavior
| `add_entity` | Returns one `Entity`, not a deduplication tuple. Sends only name, type, and description. Bolt subtype, aliases, attributes, metadata, and provider-control kwargs are not sent.
| `search_entities` | Sends query, limit, and a single type via `entity_type` (aliases `type` and `label`). Bolt `entity_types`, `subtypes`, and `threshold` are not sent. Search is workspace-wide.
| `get_entity_by_name` | Searches up to 20 results and returns the first exact case-sensitive name match, or None.
| `get_related_entities` | Returns identifying relationship dictionaries (`relType`, `targetId`, `targetName`, `targetType`), not full Entity models. Traversal kwargs are not sent.
| `get_entity_relationships` | Adapts inline relationships into Relationship models. IDs and creation times are synthesized locally; they are not stable server relationship identities.
| `get_context` | Returns an empty string. Use entity search and conversation context explicitly.
| Preferences, facts, `add_relationship` | Raise `NotSupportedError`; no corresponding hosted public operation is provided by these wrappers.
| Deduplication administration, local geocoding, extractor registration/linking/statistics | Bolt-only methods; not exposed by `NamsLongTermMemory`.
|===

[source,python]
----
# NAMS: retain the entity directly; no tuple unpacking.
entity = await client.long_term.add_entity("Acme Corp", "ORGANIZATION")
----

=== wait_for_extraction

Wait for asynchronous extraction. Pass a conversation ID for pipeline status and optionally `expected_names` or `predicate` for entity confirmation. Returns False on timeout; check the result. A query with `min_results=1` alone can match unrelated existing workspace entities. On bolt, this method is a no-op returning True.

// contract: nams/long_term.py:NamsLongTermMemory.wait_for_extraction
[source,python]
----
async def wait_for_extraction(
    *,
    query: str | None=None,
    expected_names: list[str] | None=None,
    min_results: int=1,
    predicate: Callable[[list[Entity]], bool] | None=None,
    timeout: float=30.0,
    interval: float=1.0,
    session_id: str | None=None,
    **kwargs: Any,
) -> bool: ...
----

=== set_entity_feedback

NAMS only. `positive` maps to userScore 1.0 and confirmed True; `negative` maps to 0.0 and False; a numeric string maps to userScore. Explicit `user_score` and `confirmed` kwargs override this mapping. This does not store an arbitrary feedback comment.

// contract: nams/long_term.py:NamsLongTermMemory.set_entity_feedback
[source,python]
----
async def set_entity_feedback(entity_id: UUID | str, feedback: str, **kwargs: Any) -> None: ...
----
