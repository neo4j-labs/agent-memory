To retain an explicit user preference and its revision history, attach it to the user identifier, optionally scope it to an entity, and supersede the old record after creating a replacement.

== 2. Apply the task function

Store a preference for a user, then supersede it with a revised value while keeping both records in history. The recipe disables embedding-based preference deduplication for these independent user revisions. The current duplicate lookup can reuse a preference node across users; superseding a shared node can therefore affect every linked user's active view. `generate_embedding=False` avoids that lookup here, at the cost of omitting vectors for semantic preference search.

== Retrieve preferences for an authorized user

`get_preferences_for(user_identifier, applies_to=...)` follows the explicit user association. `active_only=False` includes superseded records; `as_of` filters validity intervals. Validate the caller before selecting the identifier. `get_preferences_by_category` and `search_preferences` are broader queries without the same user-scoped contract.

The returned `Preference` model has `category`, `preference`, `context`, `confidence`, and inherited memory fields. It has no `value` or `source_message_id` argument. Use `context` and metadata to record application evidence; do not present that metadata as a graph provenance edge.

== Use preferences in an application

The task above records explicit statements. Inferring preferences from behavior requires your own extraction and validation policy; there is no `extract_preferences` convenience method on `long_term`, nor does this task automatically learn a user's budget. For a complete application that includes saved preferences in its model request, use xref:tutorials/conversation-memory.adoc[the conversation tutorial].

There are no `update_preference` or `delete_preference` wrappers. Supersession preserves history; a different mutation or deletion requires an application-owned Bolt graph operation. See xref:reference/api/long-term.adoc[the API reference] and xref:how-to/privacy-and-audit.adoc[privacy and audit tasks].
