= Merge a reviewed entity pair
:page-product: agent-memory
:page-pagination:
:toclevels: 2
:sectanchors:

To combine two known duplicate entities, choose the source and target explicitly, merge that pair, and verify the source marker and target aliases. Review semantic candidates before applying the same operation to user data.

== Review semantic candidates

To let new writes use the configured policy, leave `deduplicate=True` on `store.add_entity`. Inspect the returned `DeduplicationResult.action`, `matched_entity_id`, and `similarity_score`. Default thresholds are 0.95 for automatic merging and 0.85 for review; their suitability depends on the corpus and embedding model.

`find_potential_duplicates(limit=...)` returns `(entity1, entity2, confidence)` tuples for pending pairs. After an application review, call `review_duplicate(source_id, target_id, confirm=True)` to merge or `confirm=False` to reject the flag. An empty review queue is a valid result. `get_deduplication_stats()` returns a dataclass with `total_entities`, `merged_entities`, `same_as_relationships`, and `pending_reviews`.

anchor:_manual_entity_merging[]

== Check relationship coverage before merging

The current merge query copies incoming `MENTIONS` links and eligible `SAME_AS` links, adds the source name as a target alias, and marks the source. It does not delete the source or transfer every `RELATED_TO`, `EXTRACTED_FROM`, or custom relationship. Inspect those edges and decide how your application will reconcile them before merging a populated graph.

Known aliases, type consistency, and a labeled sample of true/false duplicates help assess a policy. Do not choose automatic thresholds from an unmeasured “safe” universal value. See xref:explanation/resolution-deduplication.adoc[resolution and deduplication] for the distinction between the two mechanisms, and xref:reference/api/long-term.adoc[the complete API] for configuration and return models.
