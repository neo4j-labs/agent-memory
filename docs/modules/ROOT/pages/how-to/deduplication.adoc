== Review semantic candidates

To let new writes use the configured policy, leave `deduplicate=True` on `store.add_entity`. Inspect the returned `DeduplicationResult.action`, `matched_entity_id`, and `similarity_score`. Default thresholds are 0.95 for automatic merging and 0.85 for review; their suitability depends on the corpus and embedding model.

`find_potential_duplicates(limit=...)` returns `(entity1, entity2, confidence)` tuples for pending pairs. After an application review, call `review_duplicate(source_id, target_id, confirm=True)` to merge or `confirm=False` to reject the flag. An empty review queue is a valid result. `get_deduplication_stats()` returns a dataclass with `total_entities`, `merged_entities`, `same_as_relationships`, and `pending_reviews`.

== Check relationship coverage before merging

As of SDK 0.6.0, the merge query adds the source name as a target alias and copies the source's edges of these types onto the target — inbound `MENTIONS`, `RELATED_TO` in both directions, `SAME_AS`, outbound `EXTRACTED_FROM` and `EXTRACTED_BY` provenance, inbound `APPLIES_TO`, and inbound `TOUCHED` — then marks the source with `merged_into`/`merged_at`. It copies rather than deletes: the source keeps its own edges so the merge stays reversible and auditable, and each copied edge carries the source edge's `id` plus a `migrated_from` property. Relationship types outside that list are not transferred automatically; inspect those edges and decide how your application will reconcile them before merging a populated graph.

Known aliases, type consistency, and a labeled sample of true/false duplicates help assess a policy. Do not choose automatic thresholds from an unmeasured "safe" universal value.

== Verification

Expected: `Verified: reviewed pair merged into ...; merged nodes=...`. The assertions check the source's `merged_into` value and the target's alias list rather than assuming a particular embedding score.
