= Record and verify a failed tool call
:page-product: agent-memory
:page-pagination:
:toclevels: 2
:sectanchors:

To diagnose an unsuccessful tool action, create a trace, add the action as a step, record its error with `ToolCallStatus`, and complete the trace with a structured outcome. Read back the step and tool call to verify that the failure was retained.

anchor:_complete_the_trace[]

== Complete every started trace

In real tool code, wrap the actual operation in `try`/`except`, record the appropriate `ToolCallStatus`, and call `complete_trace` on success and failure paths. `record_tool_call` accepts `status`, `error`, and integer `duration_ms`; it has no `success` keyword. `complete_trace` accepts an outcome string or `TraceOutcome`; it has no `error` keyword.

The xref:tutorials/conversation-memory.adoc[chatbot tutorial] provides a complete success path and completion after a failed model request. Optional `triggered_by_message_id` creates an `INITIATED_BY` link. Use `touched_entities`/`EntityRef` for explicit action provenance, and async hooks for follow-up writes.

anchor:_query_past_traces[]

== Inspect recorded outcomes

Use `get_trace_with_steps(trace_id)` and inspect `trace.steps` and `step.tool_calls`. Use `get_session_traces` for a known session, `list_traces` for supported filters, and `get_similar_traces` for ranked candidates. There are no `get_steps`, `get_tool_calls`, `get_traces`, `search_traces`, or `delete_trace` wrappers.

Similarity is stored in trace metadata; `search_steps` returns result wrappers with step and parent-task information. A similar successful trace is evidence for the application to assess, not proof that a new action will succeed. For evaluation and pruning, follow xref:how-to/evaluation.adoc[memory evaluation] and xref:how-to/audit-reasoning.adoc[reasoning audit tasks]. Exact filters and hooks are in xref:reference/api/reasoning.adoc[the reasoning reference].
