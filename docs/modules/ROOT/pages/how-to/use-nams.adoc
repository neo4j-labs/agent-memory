= Connect a Python application to NAMS
:page-product: agent-memory
:page-pagination:
:toclevels: 2

To store and retrieve messages through NAMS, configure the Python client with a workspace key and use the conversation ID returned by the service.

// Retain former section URLs at the current related topic.
== Prerequisites

anchor:_env_var_reference[]anchor:_next_steps[]

* Python 3.10+ and a POSIX shell.
* A data-plane workspace key and the intended NAMS endpoint. Obtain these from your workspace administrator or the https://memory.neo4jlabs.com[dashboard]. A key's permissions and workspace association determine access; two keys can belong to the same workspace.
* Review xref:reference/backend-capabilities.adoc[backend capabilities] before moving existing Bolt code. Configuration alone does not migrate stored data or make all Bolt operations available.

This procedure uses the published Python 0.6.0 package. It performs a message write and leaves the test conversation available for inspection.

== 1. Install the client

anchor:_custom_endpoint_private_deployments[]

Create a directory for the connection check and install the package in its own environment:

[source,bash]
----
mkdir nams-connection-check
cd nams-connection-check
python3 -m venv .venv
source .venv/bin/activate
python -m pip install 'neo4j-agent-memory[nams]==0.6.0'
export MEMORY_API_KEY='nams_replace_with_workspace_key'
export MEMORY_ENDPOINT='https://memory.neo4jlabs.com/v1'
----

Keep the key out of source control. A workspace header is needed only when required by your deployment; see xref:reference/configuration.adoc#nams[NAMS settings] for explicit precedence and fields.

== 2. Save a complete connection check

anchor:_configure[]anchor:_first_request[]

Save this as `check_nams.py` in `nams-connection-check/`:

.Save as `check_nams.py`
[source,python]
----
import asyncio
from uuid import uuid4

from neo4j_agent_memory import NamsSettings, connect


async def main():
    client = await connect(NamsSettings())
    try:
        conversation = await client.short_term.create_conversation(
            f"connection-check-{uuid4().hex[:8]}"
        )
        conversation_id = str(conversation.id)
        content = "Connection check: the workshop starts in Denver."
        message = await client.short_term.add_message(
            conversation_id, "user", content
        )
        history = await client.short_term.get_messages(conversation_id)
        assert any(item.id == message.id and item.content == content for item in history)
        print(f"Verified message {message.id} in conversation {conversation_id}")
    finally:
        await client.close()


asyncio.run(main())
----

== 3. Run and verify

anchor:_verify[]

[source,bash]
----
python check_nams.py
----

Success prints `Verified message` followed by the returned identifiers. This verifies connection, message storage and readback. It does not certify entity extraction, long-term search scope or reasoning-trace durability. Retain the conversation ID to reopen this conversation; its display name and a user ID are not substitutes.

== Resolve a failed check

anchor:_whats_not_available_on_nams[]

* Authentication failure: confirm the key, endpoint and workspace association. Do not replace a workspace key with an admin key merely to bypass a data-plane failure.
* Rate limit or transport failure: inspect the exception and request context. Python retries only its configured status/network set; see xref:reference/rest-api.adoc[REST transport behavior]. No service pricing tier is inferred from the error.
* Unsupported operation while porting code: follow xref:how-to/migrate-to-nams.adoc[the migration procedure].

== Configuration and operational scope

anchor:_namsconfig_fields[]anchor:_bring_your_own_database_byod[]

The maintained xref:reference/configuration.adoc[NAMS configuration] and xref:reference/environment-variables.adoc[environment reference] describe constructor arguments, aliases and provider wiring. Use xref:reference/backend-capabilities.adoc#scope[the scope reference] before adding user metadata. There is no universal `user_identifier` parameter or automatic cross-conversation authorization boundary.

Workspace database provisioning and bring-your-own-database management are separate administrative service operations. Verify the deployed service's OpenAPI and workspace permissions before using them; they are not part of this connection check. Client-side extraction, embeddings, resolution, enrichment and geocoding settings do not configure the NAMS extraction service.
