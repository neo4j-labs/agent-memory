= Extract and inspect entity candidates
:page-product: agent-memory
:page-pagination:
:toclevels: 2
:sectanchors:

To extract entity candidates with a local model, select a supported domain schema, run extraction on the input, and inspect the returned names and types before persistence.

image::diagrams/extraction-pipeline.svg["Configurable extraction stages combine candidate results",width=100%,link=self]

anchor:_prerequisites[]

== 1. Install the local extractor

Use Python 3.10 or newer and a POSIX shell. Prepare the example files and install the required extra:

include::partial$python-tutorial-setup.adoc[]

[source,bash]
----
python -m pip install 'neo4j-agent-memory[gliner]==0.6.0'
----

The maintained program `extraction_recipes.py` supplies its own imports, source texts, and event-loop entry point. It downloads the GLiNER model on first inference; allow disk space and network access for the download. These commands do not connect to a database or require an LLM API key.

include::partial$python-extraction-recipe-file.adoc[]

== 2. Configure and run the extraction

The runner constructs `GLiNEREntityExtractor.for_schema("business")` and uses the first built-in fictional source text. Relation and preference extraction are disabled for this entity-only task.

The following function is included from the complete program. Run the maintained file with the command below it.

[source,python]
----
include::example$extraction_recipes.py[tags=extract]
----

[source,bash]
----
python extraction_recipes.py extract
----

== 3. Verify the result

Expected: candidate names, POLE+O types, optional subtypes, and confidence values, followed by `Verified: ... candidate entities returned; inspect their accuracy`. No entities causes an explicit error, not a successful extraction claim.

The command raises on the documented failure conditions. Inspect candidate names, types, and confidence against source text before storing them. Counts alone do not measure extraction accuracy.

== Store candidates with provenance

A standalone extractor returns `ExtractionResult`; it does not persist nodes. Its entities expose `name`, `type`, `subtype`, and `confidence`. A relation exposes `source`, `target`, and `relation_type`. Store accepted entities with `add_entity` and attach source evidence using `link_entity_to_message`. Entity storage has no `confidence` parameter; keep extraction confidence on the provenance link or in metadata.

The xref:tutorials/knowledge-graph.adoc[document tutorial] includes a complete write/readback path and skips ambiguous relationship endpoints. Avoid automatic extraction on `add_message` when you also run and store an explicit extraction, or you may duplicate work and records.

For conditional/multi-stage extraction, use the supported constructor options rather than undocumented callbacks. `FIRST_SUCCESS` stops when a stage reaches the configured minimum; other merge policies can also stop with `stop_on_success=True`. Stage execution success does not imply factual correctness. See xref:reference/extractors.adoc[all extractor and pipeline options].
