Restore a Strands conversation through `Neo4jSessionManager`, then choose additional retrieval or tool surfaces only when your application needs them. The selected program verifies a fresh-process history restore before another model request.

== 1. Prepare the selected environment

Install the AWS CLI before running the identity check below.

anchor:_installation[]
anchor:_model_ids[]

Use Python 3.10+, a POSIX shell, a dedicated AuraDB instance and AWS credentials authorized for both the selected Bedrock chat model/inference profile and Titan V2 embeddings. The `[strands]` extra selects the SDK's supported 1.x range. The TypeScript integration has different surfaces: see xref:how-to/typescript/strands.adoc[Strands for TypeScript].

Follow xref:tutorials/first-agent-memory.adoc#_step_2_set_up_neo4j[the Aura connection setup] for a dedicated test instance, then copy its URI, username and password into the exports below.

== Troubleshooting and cleanup

anchor:_error_handling[]
anchor:_performance_tips[]
anchor:_reduce_latency[]
anchor:_reduce_costs[]

Confirm account/region/model access separately from authentication. `BedrockModel` accepts a deployment-specific model ID; aliases do not authorize it. Use a database whose vector dimensions match Titan V2's 1024 dimensions. Close the session manager to flush its buffered final message, and retain the state file when restarting. Remove the dedicated example database and local `strands-tutorial-session.txt` only when inspection is complete.

Pick a surface before configuring either class: use `Neo4jSessionManager` to transparently persist and restore the whole conversation transcript, and add `Neo4jMemoryStore` only when the agent also needs to pull retrieved memory into its own reasoning loop through `MemoryManager`. The two paragraphs below cover each in turn.

`Neo4jSessionManager` persists and restores transcripts; it does not require the model to invoke a memory tool. Its constructor requires exactly one of `settings=` or `memory_client=`. Prefer settings-owned lifecycle for a synchronous Strands application. Optional `record_tool_calls=True` records observed calls; `restore_limit` controls how much history is loaded.

`Neo4jMemoryStore(Neo4jMemoryStoreConfig(...))` implements Strands' memory-store surface. Configure it on `MemoryManager(stores=[store])` for agent-loop retrieval. `name` identifies a store, `settings` or `client` supplies a backend, and `conversation_id` selects the sink where applicable. Store extraction is off by default; a read-only configuration should not be described as capturing every turn. See https://github.com/neo4j-labs/agent-memory/tree/main/examples/strands-memory-store[the complete maintained memory-store example] for its lifecycle and verified settings.

Choose one writer when combining a store and session manager. Leave store extraction disabled when the session manager owns transcript writes; otherwise a turn can be written/extracted twice. Avoid duplicate retrieval injection from both adapters. Strands invocation-triggered extraction and backend entity extraction are separate stages; a successful write does not prove every derived entity is ready.

`context_graph_tools(...)` exposes the pull-based tools `search_context`, `get_entity_graph`, `add_memory` and `get_user_preferences` for Bolt. `nams_context_graph_tools(...)` exposes hosted operations with a workspace key. Tool names describe available actions; the model can choose not to call them. Tool factories cache clients; call `clear_client_cache()` when ending their lifecycle. Provider pass-through helpers configure extraction separately from Strands' own inference.

Await writes, check the applicable extraction lifecycle, and apply workspace/database authorization before another agent retrieves results. A shared graph makes permitted records available through retrieval; it does not broadcast every fact immediately to every agent. `user_id` and session grouping do not provide universal entity isolation.
