== Three memory types, one graph

anchor:_framework_integrations[]anchor:_python_neo4j_agent_memory[]

.Library memory layers and backend boundaries
image::diagrams/the-three-layer-memory-architecture.png["Conversations, entities and reasoning records connected through the selected memory backend",width=100%,link=self]

[cols="1,2,3",options="header"]
|===
|Memory layer |Stored information |How applications use it
|Short-term
|Conversation messages and metadata
|Read a selected conversation or search messages; review the operation's scope before combining results into a prompt
|Long-term
|Entities and graph relationships; preferences and facts on Bolt
|Retrieve relevant entities and, where supported, explicitly manage structured preferences and facts
|Reasoning
|Application-supplied traces, steps and tool calls
|Inspect recorded actions and results; this does not expose a model's hidden reasoning
|===

See xref:explanation/memory-types.adoc[memory types] for the conceptual model and xref:reference/index.adoc[reference] for exact APIs. Persistence stores data; retrieval and a model call must be wired into the application for that data to influence a later answer.

== Sharing memory between agents

anchor:_podcast_lennys_podcast_memory_explorer_flagship[]anchor:_newspaper_full_stack_chat_agent[]anchor:_typescript_neo4j_labsagent_memory[]anchor:_architecture[]anchor:_requirements[]

Several agents can use the same workspace or database. Shared entities can connect their work, while conversation IDs identify individual conversations. Those identifiers are not universal access-control or query-filter guarantees. NAMS uses workspace authentication as its tenancy boundary; Bolt applications must choose authorized database boundaries and explicitly scoped reads.

The current Bolt semantic-message search accepts `session_id` without applying it to its Cypher query. Do not infer privacy from that argument or from combined context generation. See xref:how-to/multi-tenancy.adoc[associate users and select scoped reads] and xref:explanation/multi-agent-sharing.adoc[sharing tradeoffs].

== Graph and extraction capabilities

anchor:_entity_extraction_pipeline[]

* Connect conversation messages to entities and recorded actions in a graph.
* Combine semantic retrieval with graph queries supported by the chosen backend.
* Configure local or remote extraction/embedding providers on Bolt; NAMS manages its processing pipeline.
* Add geocoding or enrichment on Bolt when explicitly enabled and configured. See xref:how-to/entities.adoc[entity tasks].
* Integrate with supported agent frameworks through xref:how-to/integrations/index.adoc[Python integrations] or xref:how-to/typescript/integrations-overview.adoc[TypeScript integrations].

Choose batch sizes and extraction limits for your model and workload; no universal large-document cutoff or throughput guarantee applies.
